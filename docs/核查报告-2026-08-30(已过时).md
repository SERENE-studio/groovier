## 2. 性能开销

- [结论] 热路径已接近下限,无高收益优化点:
  - 钉子无覆盖时 = 一次 `ConcurrentHashMap.get` + null 返回([GroovierHooks.java#L46-62](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/hooks/GroovierHooks.java#L46-L62)),语义必需,无法再降。
  - 重载已分层:prepare(扫描+编译)在后台线程,apply 不做编译([ScriptManager.java#L31-32, L100-133](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/sandbox/ScriptManager.java#L100-L133)),层1哈希增量缓存避免重复编译([ScriptManager.java#L140-168](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/sandbox/ScriptManager.java#L140-L168))。
- [低收益] `hashFile` 每次重载全量读文件算 SHA-256([ScriptManager.java#L171-181](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/sandbox/ScriptManager.java#L171-L181))。脚本文件小,收益仅在大脚本库;若要优化可先用 `size+mtime` 预筛,哈希仅对疑似变更文件计算。
- [低收益] `resolveOwnerScript` 沿闭包 owner 链上溯 + 静态表反查([GroovierEventManager.java#L68-82](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/event/GroovierEventManager.java#L68-L82))——仅注册时执行一次,非事件热路径,无需处理。

## 4. 业务逻辑 bug

- [一般] 脚本启停嵌套执行窗口:`apply` 执行脚本期间未设置 `inChange`([ScriptManager.java#L101-133](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/sandbox/ScriptManager.java#L101-L133)),若脚本 A 在执行中改写 `groovier.enabled.<B>` 触发 `onGlobalChanged`,会在 A 未完成时重入执行脚本 B,与"apply 顺序执行"的时序假设冲突。触发条件苛刻(脚本需在初始化期改启停键),建议在 apply 外层同样置 `inChange`。
- [一般] 事件回调内注册监听器归属失败即泄漏:owner 链上溯不到 `Script` 实例时返回空串,监听器挂到 `""` 分组([GroovierEventManager.java#L58-64](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/event/GroovierEventManager.java#L58-L64)),`unregisterScript("")` 永不被调用——脚本禁用后该监听器仍存活,直至下次 reload 的 `reset()`。场景:辅助类(非脚本 owner)中定义的闭包调用 `listen`。
- [轻微] 共享静态表线程安全:`scriptClasses` 为普通 `HashMap`([ScriptManager.java#L41](file:///d:/bluesky_fantaste/groovier/src/main/java/com/bluesky/groovier/sandbox/ScriptManager.java#L41)),写入发生在 server thread(apply),读取可能来自其他线程的事件回调(`lookupScriptPath`),无同步。实际竞争窗口窄,建议换 `ConcurrentHashMap`。
